# LSS 策略研究系统需求规格

## 1. 文档信息

- 版本：`2.0`
- 状态：当前实现基线
- 适用范围：沪深市场研究、策略筛选、次日计划、当日实盘、回测和复盘
- 行情来源：`rustdx native`（迁移前归档保留原数据源）
- 时区：`Asia/Shanghai`

## 2. 产品目标

系统在每个交易日收盘后生成下一交易日的条件观察计划，并在交易日盘中持续采集候选股票
行情，结合开盘、价格、板块强度、时间窗口和不可逆放弃条件，给出可解释的实时研究建议。

系统必须解决：

1. 行情、策略输入、计算结果、状态变化和报告均有持久化落点。
2. 行情采集、实时计算、策略决策、查询展示相互解耦。
3. 任一服务重启后可以恢复状态、重放数据并解释历史判断。
4. 数据过期、缺失或来源异常时停止生成入场确认。
5. 全链路不包含自动下单和券商账户操作。
6. 策略参数不可原地覆盖，参数修改形成可追溯的新策略；仅展示名称可原地修正。
7. 历史研究、严格可买模拟和盈利优化与当前激活策略隔离。
8. 本地集成与生产使用 Market Worker；候选计划从数据库加载，不依赖容器内报告文件。
9. 定时报告与页面刷新由常驻报告调度器处理；Web/API 扩容与后台任务容量相互独立。
10. 统一 Web/API 负责账户、多租户、SSE 和 Policy 门面；浏览器不接触内部服务凭据。
11. 行情与报告归档只有在对象写入、读回、哈希和 Manifest 核对后才算完成。

## 3. 用户与场景

### 3.1 研究用户

- 查看每日市场环境、候选评分和入选依据。
- 查看每只股票的竞价区间、入场条件、放弃条件和退出计划。
- 盘中查看最新行情、数据时效、策略状态和状态变化原因。
- 查询历史计划、历史判断和报告文件。
- 创建策略副本、查看参数差异和血缘、切换全局激活策略。
- 查看日/周/月/年研究统计、严格可买样本和 T+1 收益边界。

### 3.2 系统运维人员

- 查看采集延迟、WAL/Outbox 积压、存储健康、Worker 心跳和 API 状态。
- 对失败事件执行 WAL/Outbox 重放或隔离处理。
- 执行备份恢复、版本回滚和数据一致性校验。

## 4. 业务范围

### 4.1 包含

- 沪深主板 10cm 股票。
- 首板股票池、炸板池、连板高度和题材活跃度。
- 每个交易日 `16:30` 生成下一交易日计划，并于 `23:30` 基于最新行情覆盖更新。
- 调度进程重启时自动检查并补跑最近 7 天已到期但未完整落库的任务。
- 动态候选池的盘中盘口快照和一分钟线监控。
- 研究建议状态：等待、观察、确认待核验、放弃、不追、行情异常。
- Markdown、JSON、CSV 报告和 Web 看板。
- 不可变多策略目录、全局唯一激活状态、策略血缘和关联数据永久删除。
- 每策略每交易日一条计划/执行/实际行情汇总记录。
- 历史准确率、严格可买、T+1 收益、等权盈亏和盈利约束参数实验。
- 首页、自选、策略、次日计划、当日实盘、复盘、回测、个股分析和设置九项统一 Web 页面。

### 4.2 不包含

- 自动下单、账户登录、持仓同步和资金管理。
- Level-2、完整逐笔成交或逐笔委托能力承诺。
- 对收益率、成交概率或涨停排队结果作保证。
- 将公开人物的交易系统视为可精确复制的事实。
- 品牌预览、开发演示数据生成、强制触发预警和第三方开源发布监控。

## 5. 硬性业务规则

| 编号 | 规则 |
| --- | --- |
| BR-001 | 新采集行情数据单一来源为 `rustdx native`，不得引入 AkShare 等并行行情源 |
| BR-002 | 策略范围聚焦首板晋级二板，默认排除 ST、退市、创业板、科创板和北交所 |
| BR-003 | 策略默认成交额下限为 2 亿元；保存的策略版本可在校验范围内调整，报告必须记录实际值 |
| BR-004 | 盘中实时入场研究窗口不得晚于 `10:00:00`；当前激活策略以其不可变配置为准 |
| BR-005 | 当日最低价跌破昨日收盘价后，当前计划永久进入放弃状态 |
| BR-006 | 开盘涨幅不在策略合格区间时不得给出入场确认 |
| BR-007 | 开盘涨幅低于放弃下限或高于放弃上限时进入不可逆放弃状态 |
| BR-008 | 个股封板不能单独证明主线成立，必须结合题材上涨家数和前排助攻 |
| BR-009 | 交易时段盘口目标采集周期为 1 秒，一分钟线目标刷新周期为 60 秒 |
| BR-010 | 非交易时段采集周期降为 60 秒 |
| BR-011 | 行情时间不可核验、数据过期、昨收不一致或采集失败时暂停判断 |
| BR-012 | 候选仅供研究参考，任何输出都不得成为无条件买入或自动下单指令 |
| BR-013 | 全库最多一条未归档策略处于激活状态；激活新策略必须原子停用旧策略 |
| BR-014 | 已保存策略仅允许原地修改名称；参数、父策略和差异不可修改，参数变更必须创建子策略 |
| BR-015 | 回测或优化结果默认未激活，不得因历史盈利自动替换当前策略 |
| BR-016 | 默认一进二候选要求首板首次封板不晚于 10:30，且首板换手率位于 3% 至 18% |

## 8. 数据持久化要求

“全量持久化”指进入系统并被确认接收的行情、指标、决策、配置、运行结果和报告都有
可恢复的持久化落点，不代表所有副本永久保留。

- 原始行情：SQLite WAL 承接未确认事件，ClickHouse 热查询，TOS 长期归档。
- 策略状态：PostgreSQL 权威保存。
- 最新快照：Redis 加速，可重建。
- 报告文件：TOS 版本化保存。
- 日志、指标和追踪：独立可观测存储并配置生命周期。

具体生命周期见 [数据与存储](03-data-storage.md)。

| 编号 | 场景 | 期望结果 |
| --- | --- | --- |
| AC-001 | 候选盘中最低价跌破昨收后反弹涨停 | 状态保持“放弃”，重启后不恢复 |
| AC-002 | 09:59:59 满足条件，10:00:00 后再收到重复事件 | 不产生新的入场确认 |
| AC-003 | WAL 重放同一行情事件 | ClickHouse、状态机和审计无业务重复 |
| AC-004 | Redis 数据全部清空 | 可自动重建，权威状态不丢失 |
| AC-005 | rustdx 当前节点失败 | 自动切换节点，页面显示短暂降级和恢复时间 |
| AC-006 | 行情超过时效阈值 | 页面保留最后报价但暂停策略判断 |
| AC-007 | 服务在状态迁移后、提交 offset 前崩溃 | 重启重放后不产生重复迁移 |
| AC-008 | 同一时点的日报任务被重复调度 | 文件和数据库保持幂等，不产生重复业务记录 |
| AC-009 | 本地 WAL 已确认清理 | 可从 TOS 原始归档和权威数据库回放 |
| AC-010 | 报告生成成功 | Markdown、JSON、CSV 内容与数据库元数据一致 |
| AC-011 | 修改已保存策略参数 | 必须输入新策略名；原策略不变，创建带父子关系和参数差异的新策略 |
| AC-012 | 并发激活两条策略 | 数据库最终仅保留一条激活策略 |
| AC-013 | 刷新任务排队后切换激活策略 | Worker 使用开始执行时的激活策略并记录版本 |
| AC-014 | 一年历史回填重复执行 | 每策略每天仍只有一条记录，已有字段不被覆盖 |
| AC-015 | 盈利优化通过历史约束 | 候选保存为未激活，不自动改变当前策略 |
| AC-016 | 390x844 访问九项页面 | 无页面级横向滚动、重叠或不可操作控件 |
| AC-017 | 仅修改策略名称并保存 | 原策略名称更新，配置、父策略、差异和历史记录均不变化 |

## 10. 发布限制

以下条件任一不满足时，不得将生产版本标记为可用：

- 关键业务验收场景未自动化。
- PostgreSQL、ClickHouse 或对象存储没有备份恢复验证。
- 行情延迟、WAL 或 Outbox 积压没有告警。
- API 或事件 Schema 存在未兼容变更。
- 页面无法明确区分实时数据、延迟数据和失效数据。

## 11. v0.5.1 统一产品需求

### 11.1 产品范围

Web 是唯一客户端入口，不再提供 Android/APK。登录后的固定主导航为：

1. 首页
2. 自选
3. 策略
4. 次日计划
5. 当日实盘
6. 复盘
7. 回测
8. 个股分析

### 11.5 本次安装边界

2026-10-19 的发布按全新环境执行，不继承旧用户、策略、报告或数据库。集群系统、
镜像拉取认证及域名入口基础设施继续提供安装通道。应用凭据重新生成，TOS 必须使用
真实云端授权；未配置 SMTP 时注册验证码和邮件找回功能不得标记为已验收。
源码版本、镜像摘要、线上状态和功能限制分别记录在发布文档中。

行情归档签收必须包含已采集数据的对象写入、读回 SHA-256、行数与 Manifest 核对。
主数据归档与日终行情归档分别签收；空安装、空表或仅健康检查通过不能视为全市场
行情覆盖完成。邮件签收须限定授权收件人并确认收件箱到达，配置和验收事实见
[TOS/SMTP 验收记录](38-tos-smtp-acceptance.md)。
