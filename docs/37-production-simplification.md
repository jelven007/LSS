# 生产架构精简与功能退役

基线：`d9fb82f`，应用版本 `0.5.1`。本次为源码改造，不代表已经上线。

## 业务边界

系统服务于 A 股策略研究、选股、次日计划、盘中观察、回测和复盘。
保留身份认证、权限、数据质量、审计、历史研究与模拟验证；不引入券商委托执行。
隐藏菜单不等于无用功能，删除依据是当前部署、入口和调用关系。
数据库、用户策略、历史报告、模拟盘数据、PVC 和对象资产不在清理范围。

## 改造前问题

- 生产采用 Market Worker，但源码、依赖、本地 Compose 和 Kubernetes 基础层仍保留
  Kafka/Flink 与独立消费 Worker，形成两套实时处理路径。
- `tsp-product` 的 API 与四类 Task Worker 共用 Pod；API 的 HPA 扩容会同时复制所有
  后台进程，后台负载也会影响 Web 的扩容判定。
- Market Worker 启动先读取本地报告；生产报告目录已为临时卷，应以数据库监控计划启动。
- Policy 报告刷新写入 PostgreSQL 任务队列，但当前生产清单没有常驻
  `report-scheduler` 消费者；固定时间 CronJob 不能处理页面刷新。
- 品牌展示页、开发演示页、第三方开源发布监控不属于生产研究业务。

## 已实施范围

1. 删除已退役 Kafka/Flink 适配器、独立消费服务入口、构建与部署资源；保留事件契约、
   WAL、Inbox/Outbox、策略处理器和进程内特征计算。本地开发也使用 Market Worker。
2. API 与 Task Worker 独立部署；为 Policy 报告任务提供唯一常驻调度执行入口，避免
   与固定报告 CronJob 重复调度。调整服务发现、网络策略、资源配置和验证。
3. Market Worker 从数据库监控计划启动；健康状态反映实际依赖，移除 Kafka 健康字段。
4. 删除品牌展示、开发演示、第三方开源版本监控的入口、专属实现和专属测试；
   搜索并清理其配置、请求和文档引用。
5. 同步需求、当前架构、开发运行和发布回滚说明，执行受影响回归与构建检查。

删除包括六个旧服务入口、Kafka 适配器、Flink 镜像与 SQL、17 个无效资源排除补丁，
以及 `/branding`、`/dev`、开源发布轮询和四个专属调试接口。
不再提供 `POST /api/alerts/seed`、`POST /api/monitor-rules/seed`、
`POST /api/monitor-rules/test-ladder` 和 `POST /api/monitor-rules/trigger-ladder`。
正常告警查询/删除、规则管理和生产预警执行保留。

## 运行职责

| 运行单元 | 职责与扩容依据 |
| --- | --- |
| Web/API | React、会话、权限、查询、任务提交、SSE；按 Web 负载扩容 |
| Task Worker | TSP 持久任务、实时规则、通知、定时任务；与 API 分开配置容量 |
| Policy 报告调度 | 消费页面刷新、历史生成任务，按策略配置调度与补跑 |
| Market Worker | 数据库计划、rustdx、WAL、行情持久化、特征、策略事务与决策投影 |
| Compute | 固定计算入口、并发限制、取消和回收；无业务密钥，拒绝出网 |
| 公共行情平台与参考同步 | 不可变行情版本、证券和板块参考数据 |

PostgreSQL 保存业务事实，ClickHouse 保存行情历史，Redis 保存可重建投影，TOS 保存
对象资产。TSP 公共行情文件暂保留 NAS，不在没有替代读取链路时强行迁走。

## 可靠性约束

- 原始行情先进入 WAL；主处理成功后确认，失败可重放。
- 策略状态、Inbox、决策和 Outbox 同一事务提交；Redis 决策投影独立重试。
- 数据过期或缺失时暂停判断；保留交易日、复权、T+1、费用与不可成交约束。
- 服务重建不依赖历史报告被复制到容器，任务执行状态仍由持久库负责。
- Task Worker 直接检查数据库与公共行情，避免等待依赖 Worker 心跳的 API readiness。
- 报告调度保持单副本 Recreate；临时报告完成标记丢失后允许幂等重算，不能把部分
  已入库的计划误判为所有报告对象都成功归档。
- 退役源码由 Git 历史追溯；线上回滚使用经过验证的旧镜像和清单。
  不删除线上资源或执行数据迁移，发布前仍需备份、制品固定与业务验收。

## 发布与回滚边界

本次没有执行线上部署、数据库迁移、数据删除或远程推送。
实际发布前先暂停旧报告 CronJob，等待存量作业完成，再启动新报告调度器。
滚动升级结束后核对旧 API 侧车已退出。Kubernetes apply 不会删除已移出清单的对象；
必须按退役清单核对旧工作负载，禁止使用全命名空间无差别 prune。
Market Worker 保留 `market-collector` StatefulSet 名称及 WAL 卷标识，避免升级创建新卷。

回滚需同时恢复旧镜像与对应清单，并停用新报告调度和独立 Task Worker，防止重复调度。
回滚到基线也会恢复基线的报告队列消费缺口，不能宣称功能等价。历史库、策略、对象、
PVC 和本地未提交的 PostgreSQL 权限修改保持原样。
